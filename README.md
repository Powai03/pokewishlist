## Contexte

Projet fil rouge du cours **IIM A4 — CI/CD** : une petite application Nuxt sert de support pour construire, étape par étape, une **intégration continue** (TP CI : lint, format, types, tests, build sur chaque PR) puis un **déploiement continu** (TP CD : base de données, API sur AWS, déploiements SSR et SSG automatiques, migrations, tests de bout en bout, smoke tests, rollback, couverture).

## Ce que fait l'application

- **Wishlist de Pokémon de la 5e génération** (région d'Unys, n°494 à 649) : recherche via [PokéAPI](https://pokeapi.co), ajout, capture, retrait ; **6 Pokémon maximum**, sans doublon.
- **Fiche de chaque Pokémon** (`/pokemon/snivy`) : nom, catégorie, types, taille, poids, description, statistiques, et un bouton **Like**.
- **4 langues** (anglais par défaut, français, espagnol, japonais), interface et messages de l'API.
- **Architecture** : front **Nuxt** (Vue) · API **Hono** (TypeScript) sur **AWS Lambda** + API Gateway · base **PostgreSQL** (Supabase).

En ligne : [site SSR (Vercel)](https://pokewishlist-nu.vercel.app) · [site statique (S3 + CloudFront)](https://d7gp7a220g21z.cloudfront.net) · [API (AWS)](https://r3as2k0zxl.execute-api.eu-west-1.amazonaws.com/health)

## Lancer le projet

Prérequis : **Node.js 22+** et npm.

```bash
# API (port 3002) — sans DATABASE_URL, la wishlist est gardée en mémoire
cd api && npm ci && cp .env.example .env && npm run dev

# Front (port 3000), dans un autre terminal
npm ci && npm run dev
```

Base de données (facultatif) : créer un projet Supabase, exécuter `supabase/init.sql`, mettre la chaîne de connexion dans `api/.env` (`DATABASE_URL`), puis `cd api && npm run migrate`.

Vérifications (les mêmes qu'en CI) :

```bash
npm run lint && npm run format:check && npm run typecheck && npm run test:coverage
npm run check:locales                      # clés des traductions
cd api && npm run lint && npm run typecheck && npm test && npm run test:db
npm run build:e2e && npm --prefix api run build && npm run e2e   # tests de bout en bout
```

Déploiement : automatique après chaque merge sur `main` (pipeline ci-dessus). Retour arrière : **Actions → Rollback → Run workflow**. Infrastructure AWS (une seule fois) : `bash infra/aws-setup.sh` puis `bash infra/aws-ssg-setup.sh`.
